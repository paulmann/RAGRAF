# План инсталлятора RAGRAF: Windows 10/11 и Linux

Документ-план, не реализация. Составлен 23.11.2026 по указанию владельца: инсталлятор
под Windows 10/11 с проверкой на этой машине и под Linux с проверкой на `192.168.31.31`.

## 1. Что уже есть в дереве и что переиспользуется

| Что | Где | Роль в инсталляторе |
|---|---|---|
| Установщик зависимостей | `scripts/install.ps1` | единственное место установки Python-зависимостей; инсталлятор его вызывает, а не дублирует |
| Установщик развёртывания Community | `community/install.ps1` | ставит пакет и кладёт `ragraf` в PATH; параметры сверяет 24-я проверка чекера |
| Манифест поставки | `tools/release/manifest.toml` | состав дерева; инсталлятор распаковывает ровно то, что собрано по манифесту |
| Проверяльщик поставки | `tools/release/verify_release.py` | 9 правил, включая `paths` (нет путей машины автора) и `lf` (контракт переводов строк) |
| Отпечаток установки | `src/ragraf/edition.py` (`install_fingerprint`) | инсталлятор печатает отпечаток: по нему выпускается офлайн-лицензия |
| Проверка окружения | `tools/check_env.py`-класс проверок (`selftest`, `status`) | `selftest` НЕ гейт (всегда код 0) — инсталлятор проверяет `status` и `check` |

Чего нет и что придётся написать: определение «уже установлено», выбор каталога,
регистрация в PATH, служба автозапуска сторожа, удаление, миграция версии.

## 2. Общие требования к обоим платформам

1. **Идемпотентность.** Повторный запуск на установленной системе не ломает индекс и не
   переписывает `catalog/`: он говорит «уже установлено, версия X» и выходит с кодом 0.
2. **Не трогать чужие корпуса.** Инсталлятор работает только со своим каталогом
   (`%LOCALAPPDATA%\RAGRAF` на Windows, `/opt/ragraf` либо `~/.local/share/ragraf` на
   Linux) и не касается `.ragraf` других проектов.
3. **Отсутствие обязательных внешних зависимостей не валит установку.** Нет Joern, нет
   модели эмбеддингов, нет видеокарты — установка завершается, а `status` честно называет
   `capability=degraded` и причину (инвариант «деградация вместо падения»).
4. **Python.** Требуется `>=3.13`. Если интерпретатора нет — не тянуть его молча из сети,
   а назвать, что нужно, и предложить `--install-python` отдельным решением владельца.
5. **Проверка после установки — три команды**, все три обязаны пройти:
   `ragraf --version`, `ragraf ensure <пробный проект>`, `ragraf -p <config> check`.
6. **Удаление оставляет данные.** `uninstall` убирает программу и PATH, а каталог
   состояния (`catalog/`, `index_rev`) сохраняет и печатает его путь: там лицензия и
   накопленный индекс; удаление только по `--purge`.
7. **Откат.** Windows: `.bak-<метка>` рядом с каталогом установки. Linux: прежний каталог
   переносится в `/opt/ragraf.bak-<метка>` (тот же приём, что у
   `tools/release/replace_staging_tree.ps1`).
8. **Лицензия.** Инсталлятор не активирует платное издание сам: он печатает отпечаток
   установки и путь, куда положить `edition.license`, `edition.license.sig`, `edition.pub`.

## 3. Windows 10/11

### 3.1 Форма поставки

- `ragraf-setup.ps1` (pwsh 7.6, `#Requires -Version 7.6`, `#Requires -PSEdition Core`),
  рядом — распакованное дерево из `RAGRAF-<версия>.zip`.
- Обёртка `ragraf-setup.cmd` для запуска из Проводника (двойной щелчок): `.cmd` обязан
  остаться в CRLF — это единственное исключение из правила LF.
- Причина не делать MSI/MSIX на первом шаге: подпись кода и упаковка требуют сертификата;
  скрипт проверяем на этой машине сегодня, MSIX — отдельное решение владельца.

### 3.2 Что делает `ragraf-setup.ps1`

| Шаг | Действие | Проверка |
|---|---|---|
| 1 | `Get-Command pwsh` → версия ≥ 7.6, иначе отказ с кодом 3 | `$PSVersionTable.PSVersion` |
| 2 | `Get-Command python` → версия ≥ 3.13 | `python -c "import sys;print(sys.version_info[:2])"` |
| 3 | каталог установки по умолчанию `[Environment]::GetFolderPath('LocalApplicationData') + '\RAGRAF'`; `-Prefix` переопределяет | `Test-Path` |
| 4 | если там уже есть `src\ragraf\__init__.py` — читать версию; равна ставимой → «уже установлено», код 0; иначе перенос в `RAGRAF.bak-<yyyyMMdd-HHmmss>` | сверка `__version__` |
| 5 | распаковка дерева, `scripts\install.ps1 -Prefix <каталог>` (зависимости) | код возврата установщика |
| 6 | PATH пользователя: `[Environment]::SetEnvironmentVariable('Path', …, 'User')`, без дублей | чтение переменной после записи |
| 7 | `ragraf --version` и `ragraf edition --fingerprint` | код 0 и совпадение версии с деревом |
| 8 | `ragraf ensure <временный проект из 3 файлов>` + `check` | `status: actual`, `capability` назван |
| 9 | итог: версия, каталог, отпечаток, что осталось настроить (Joern, модель, лицензия) | печать в конце |

### 3.3 Проверка на этой машине (обязательные прогоны)

1. Чистая установка в пустой `-Prefix` (песочница во временном каталоге) → код 0.
2. Повторный запуск → «уже установлено», код 0, каталог `catalog/` не изменён
   (сверка sha256 до/после).
3. Установка поверх другой версии → `.bak-*` создан, `ragraf --version` даёт новую.
4. Отсутствие Python в PATH (подмена PATH в дочернем процессе) → код 3 и причина.
5. Отрицательные прогоны: `-Prefix` внутрь индексируемого проекта → отказ (иначе
   инсталлятор попадёт в свой индекс); `-Prefix` в `C:\Windows` → отказ.
6. `uninstall` без `--purge` → программы нет, `catalog/` цел; с `--purge` — удалён.

## 4. Linux (`192.168.31.31`, Debian 12, пользователь `cbs-test` без sudo)

### 4.1 Форма поставки

- `ragraf-install.sh` (bash, `set -euo pipefail`), тот же архив.
- Системная установка (`/opt/ragraf`) требует root — отдельный режим `--system`;
  без root ставится в `~/.local/share/ragraf` с симлинком `~/.local/bin/ragraf`.
- Режим без sudo — то, что можно проверить на `cbs-test` сегодня; `--system`
  проверяется на `root@192.168.31.31` отдельным прогоном (сервер 31, не боевой сайт).

### 4.2 Что делает `ragraf-install.sh`

| Шаг | Действие | Проверка |
|---|---|---|
| 1 | `python3 -c 'import sys; assert sys.version_info >= (3, 13)'` | код 3 и печать найденной версии |
| 2 | выбор корня: `--prefix`, `--system`, по умолчанию `~/.local/share/ragraf` | `id -un`, `id -u` |
| 3 | существующая установка → сравнение версий, перенос в `ragraf.bak-<метка>` только при `--upgrade` | `diff -q` |
| 4 | распаковка, `python3 -m venv .venv` внутри каталога (в отличие от Windows, где берётся системный Python) | `./.venv/bin/python -V` |
| 5 | `pip install -e ".[secrets]"` — PyNaCl обязателен для хранилища и лицензии | `ragraf edition` отвечает `valid`/`community`, не `unverifiable` |
| 6 | симлинк в `~/.local/bin` или `/usr/local/bin` | `command -v ragraf` |
| 7 | `ragraf --version`, `ragraf ensure` на временном проекте, `check` | коды 0 |
| 8 | опционально `--service`: unit `ragraf-watch.service` для сторожа | `systemctl is-enabled` (только с root) |

### 4.3 Проверка на 192.168.31.31

1. `cbs-test`: установка в `~/.local/share/ragraf` (без sudo) → `command -v ragraf`, версия.
2. Повторный запуск → «уже установлено».
3. `root`: `--system --prefix /opt/ragraf` в отдельный каталог, не `/var/www/*`;
   `--service` проверяется на `systemctl is-enabled` и `journalctl -u` после старта.
4. Отрицательный прогон: `--prefix /var/www/ragraf.ru` → отказ (боевой каталог сайта).
5. Отсутствие сети для pip — отказ с причиной (не «тихая» установка без PyNaCl).
6. После проверки каталог `cbs-test` удаляется, `/opt/ragraf` остаётся только если
   владелец решит ставить постоянно.

## 5. Общая проверка «инсталлятор не врёт»

Инсталлятор обязан **падать** на четырёх заведомых порчах — по образцу
`tools/release/gate_release.py`, где гейт, никогда не падавший, считается бесполезным:

1. архив без `src/ragraf/__init__.py`;
2. версия в `pyproject.toml` не совпадает с `__version__`;
3. нет Python нужной версии;
4. каталог установки внутри индексируемого проекта.

Проверка оформляется как `tools/installer/selftest.py`, который раз за разом портит копию
архива и требует отказа с названной причиной.

## 6. Порядок работ

1. Windows: `ragraf-setup.ps1` + `.cmd`, прогоны из §3.3 на этой машине.
2. Linux: `ragraf-install.sh`, прогоны из §4.3 на `192.168.31.31` (`cbs-test`, затем root).
3. `tools/installer/selftest.py` — четыре порчи из §5 на обеих платформах.
4. Документ `docs/02_architecture/INSTALL.md` + раздел в README (6 языков) только после
   того, как оба прогона зелёные.
5. Выпуск: инсталлятор входит в манифест (`tools/release/manifest.toml`), проверяется
   `verify_release` правилами `present`/`hash` и 25-й проверкой чекера.

## 7. Что этот план НЕ обещает

- Нет MSI/MSIX и подписи кода — на первом шаге скрипт.
- Нет автоматической установки Joern и модели эмбеддингов: это отдельные решения
  (`.tools/`, `scripts/install-joern.ps1`), и без них издание честно `degraded`.
- Нет обновления «по кнопке»: обновление — это повторный запуск установщика с `--upgrade`.
- Нет проверки на Windows Server и на других дистрибутивах Linux: заявлены Windows 10/11
  и Debian 12, остальное — по факту прогона.
