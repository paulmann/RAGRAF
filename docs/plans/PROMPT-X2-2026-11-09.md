## 2. Задача этапа

Сделать так, чтобы число в документации нельзя было разойтись с кодом молча.

1. **Модуль `src/ragraf/surface.py`** — единственный источник поверхности:
   - операции: имя, параметры с умолчаниями и типами, ключи ответа;
   - инструменты MCP, подкоманды CLI;
   - возможности изданий (имя, издание, статус, операции);
   - языки деревом и текстом, форматы реестра;
   - размеры активной ревизии (файлы, узлы, рёбра) и её `rev_id`.
   Возвращает канонический JSON (сортировка, без пробелов) и `digest`.
   `tools/surface_counts.py` становится тонкой обёрткой над ним; второго счётчика
   быть не должно.
2. **Генератор `tools/surface_gen.py`**:
   - `--write` обновляет числа ТОЛЬКО внутри размеченных блоков
     `<!-- surface:begin --> … <!-- surface:end -->` (в Markdown-файлах);
   - `--check` печатает файл, ожидаемое и фактическое и возвращает код 1;
   - идемпотентен: второй прогон ничего не меняет;
   - файлы вне своего списка не трогает (приманка в песочнице обязательна).
3. **Разметка**: шесть README (все числа поверхности — в блоках), `docs/**`, где
   числа действующие; исторические числа остаются вне блоков и не проверяются.
   Это снимает измеренную проблему «история против утверждения».
4. **Гейт**: `tests/test_documented_numbers.py` получает ВТОРОЙ вид утверждения —
   поверхность; песочница и три исхода (актуально / прошлое / выдумка)
   переиспользуются, отдельного файла-дубля не создавать. Испорченное число в
   README — ошибка с файлом и двумя значениями.
5. **Сайт**: `--write` дополнительно пишет `docs/surface.json`; релизная сборка
   кладёт его в поставку. Правка сайта — отдельным промтом; гейт проверяет
   репозиторий и честно называет границу: удалённую страницу он не осматривает.
6. **Граница с навыком**: числа `docs/skills/ragraf-core/**` остаются под
   `tools/check_skill_variants.py` (там уже есть правило `source_rules`), новый
   гейт их не дублирует, но читает тот же `surface.py`.

## 3. Чего НЕ делать

- Не заводить второй счётчик чисел и второй список документов.
- Не переписывать числа вне блоков: это история, а не утверждение.
- Не трогать `tools/check_skill_variants.py` и `VARIANTS.json`, кроме случая,
  когда меняется сам текст навыка.
- Не ходить в сеть и не проверять живой сайт из теста.
- Не менять поведение операций и изданий: этап только про числа.
- Не коммитить: в дереве нет `.git`. Если появится — подпись владельца
  `Mikhail Deynekin <Mikhail@Deynekin.com>`, переменные `GIT_AUTHOR_*`/
  `GIT_COMMITTER_*` снимать в той же команде.

## 4. Приёмка

1. `python tools/surface_counts.py` и `python tools/surface_gen.py --check` дают
   одинаковые числа на неизменном дереве.
2. Порча числа в README (например 70→69) → `--check` код 1, сообщение называет
   файл, ожидаемое и фактическое; `--write` возвращает к 70.
3. `--write` идемпотентен: второй прогон — «без изменений».
4. Приманка: файл с такой же строкой вне списка не изменён.
5. Число внутри блока навыка по-прежнему ловит `check_skill_variants`.
6. `tests/test_documented_numbers.py` — зелено, проверок стало больше (было 62).
7. `docs/surface.json` содержит операции, инструменты, возможности, ревизию и
   размеры; `digest` воспроизводим.
8. `python tools/check_bom_crlf.py` — чисто; новые файлы BOM=False, CRLF=False.
9. `python tools/check_line_refs.py` — 0 неверных ссылок после правок документов.
10. `python tools/release/check_pro_delivery.py` — код 0 (в новых документах нет
    абсолютных путей автора).

## 5. Формат отчёта

1. Задача (1–2 строки) и что изменено (`файл:строка`).
2. Измеренное состояние до/после (операции, инструменты, возможности, ревизия).
3. Как устроен `surface.py`: что считается и откуда (для каждого числа — источник).
4. Приёмка: команды и вердикты.
5. Риски и что осталось.
6. Откат: какие файлы и как вернуть.
7. Использование RAGRAF: ревизия, число обращений, доля фактов со ссылкой.
