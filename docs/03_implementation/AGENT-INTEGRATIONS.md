# Агентские интеграции: что считается поддержкой

Документ описывает часть A плана «Агентские интеграции» (этапы 6–7): двенадцать
продуктов, уровни поддержки и то, что проверяется машиной, а что остаётся
человеку. Главное правило: **«упомянуто в README» поддержкой не считается**.

## 1. Пять уровней

| Уровень | Что сделано | Чем проверяется |
|---|---|---|
| L0 | продукт установлен на машине-стенде (192.168.31.103) | `--version` клиента; на рабочей машине не ставим |
| L1 | шаблон конфигурации MCP в `integrations/<slug>/` | `tools/check_integrations.py`: разбор шаблона |
| L2 | смоук: клиент вызывает `ragraf_ensure` и `ragraf_search`, в ответе есть `path:line` | `integrations/<slug>/smoke.ps1`, коды возврата 0/1/2/3 |
| L3 | автоматическая проверка в чекере | `tools/Invoke-ProjectDoctrine.ps1`, 46-я проверка |
| L4 | границы названы: что не работает и почему | раздел «Границы» в README интеграции |

L0 — **условие** проверки, а не поддержка: установленный клиент без конфигурации
и смоука ничего не даёт. Требование к сдаче интеграции — L1..L4.

Таблица — **источник истины о уровнях**: `tools/check_integrations.py` сверяет её
с `integrations/index.json` и падает, если набор продуктов или уровней разошёлся.

LangChain отличается от остальных одиннадцати тем, что это **библиотека, а не
клиент**: у неё нет ни GUI, ни своего конфигурационного файла MCP. Поэтому
поддержка здесь означает не «клиент подключается к серверу», а «в библиотеке есть
наши типы»: `RAGRAFRetriever` (`BaseRetriever` → `Document[]` с `path:line`),
семь инструментов агента и MCP-путь через `langchain.mcp.MCPAdapter`. L2 у неё
машинный, а не ручной: смоук запускает Python и проверяет адрес в ответе.
Замеры и границы (бета `langchain.mcp`, несовместимость `langchain-mcp-adapters`
с `mcp` 2.x, переиндексация на стороне MCP-сервера) — в
`integrations/langchain/README.md` и в §7 настоящего документа.

## 3. Что измерено, а что нет

**Измерено на этой машине (02.11.2026):** установлены `openclaw` 2026.10.5,
`claude` 2.1.316, `codex-cli` 0.166.0, `opencode` 1.19.5, `pi` 1.4.0; Cline
4.1.26 в VS Code; AutoClaw 1.20.0. Это L0 только для перечисленных.

**L2 не измерен ни у одного продукта, и это названо, а не замаскировано:**

| Продукт | Что ответил клиент | Код смоука |
|---|---|---|
| Claude Code | `Not logged in · Please run /login` | 3 |
| OpenClaw | `gateway agent requires credentials before opening a websocket` | 3 |
| OpenAI Codex CLI | `Not inside a trusted directory and --skip-git-repo-check was not specified` | 3 |
| Hermes, OpenCode, Pi | клиент ждёт интерактивного ввода: headless-вызов в этой среде не завершается | не запускался |

Код 3 означает «клиент не готов» (нет входа, ключа или доверия к каталогу), а не
«интеграция сломана». Полный L2 требует авторизованного клиента — это работа на
стенде 192.168.31.103 по решению владельца, а не на машине с живым индексом.

**Единственный измеренный L2 — у LangChain (03.11.2026).** Он не клиент, поэтому
проверка машинная: смоук поднимает Python, вызывает `RAGRAFRetriever` и
инструменты, требует адрес `path:line` и возвращает 0. Результат на rev-1381:
retriever — 3 документа с адресами, инструменты — 7 из 7 отвечают адресом,
MCP-путь — 74 инструмента, вызов `ragraf_search` дал `path:line`.

## 4. Как проверить самому

```powershell
python tools/check_integrations.py            # все проверки, код 1 при находках
python tools/check_integrations.py --templates # только шаблоны и README
pwsh -NoProfile -File integrations/openclaw/smoke.ps1   # L2 одного продукта
pwsh -NoProfile -File integrations/langchain/smoke.ps1 # L2 LangChain (машинный)
```

Коды смоука: 0 — ссылка `path:line` получена; 1 — клиент ответил, но адреса нет;
2 — клиент не найден; 3 — клиент не готов (нет входа, ключа или доверия).

## 5. Границы части A

* **GUI не автоматизируется.** Cline, DeepSeek Harness, AutoClaw, Cursor получают
  чек-лист из пяти шагов; каждый шаг наблюдаем человеком. Это L4, а не L2.
* **Секретов в шаблонах нет.** Ключи провайдеров и токены доступа живут в
  окружении или хранилище RAGRAF; проверка ищет значения вида «ключ: значение» и
  падает при находке.
* **Manus — облачный клиент.** Локального конфигурационного файла нет; шаблон
  описывает HTTP-транспорт, а граница названа прямо: облачный клиент не получает
  локальный корпус без решения владельца.
* **Стенд отдельный.** Чистые установки — только на 192.168.31.103: на рабочей
  машине живёт индекс, и установка клиентов «для проверки» ломает замеры.
* **Смоук — не тест модели.** Он проверяет, что клиент вызвал инструмент и привёл
  адрес; качество ответа модели — вне области RAGRAF.

## 7. LangChain: что измерено и почему выбрано так

LangChain — библиотека, а не клиент, поэтому решение «как интегрировать» здесь
означает выбор уровня внутри Python, а не настройку конфигурации. Проверено
03.11.2026 на этом дереве (rev-1364, 1058 файлов, Python 3.14.7, langchain 1.4.8).

**Что у RAGRAF есть на самом деле** — важно, потому что рекомендация «сначала HTTP
API» росла из незнания устройства проекта:

| Есть | Где | Следствие для интеграции |
|---|---|---|
| фасад из 67 операций `op_*` | `src/ragraf/facade.py` | прямой вызов в процессе — самый короткий путь |
| MCP-сервер, 74 инструмента, JSON-RPC 2.0 stdio, протокол `2024-11-05` | `src/ragraf/mcp_server.py` | межпроцессная граница уже существует |
| HTTP-поверхности поиска нет | — | HTTP API пришлось бы писать, то есть дублировать поиск |
| сторож в фасаде; у MCP-сервера `watch=True` | `src/ragraf/facade.py:1227`, `src/ragraf/mcp_server.py:2567` | прямой путь может работать без переиндексации, MCP — нет |

**Замеры задержек** (один и тот же запрос, 5 повторов на прогретом индексе):

| Путь | Первый вызов | Повторный (медиана) |
|---|---|---|
| прямой `RAGRAFRetriever.invoke` | 2 975 мс | 660 мс (650–772) |
| MCP через `langchain.mcp.MCPAdapter` | 3 371 мс (обнаружение 74 инструментов — 310 мс) | 675 мс (656–766) |

Разница на прогретом индексе — 15 мс: транспорт не узкое место, время уходит на
эмбеддинг запроса и лексический поиск одинаково с обеих сторон. Выбирать путь по
скорости бессмысленно — решают свойства.

**Выбранное решение.** Прямой адаптер (`RAGRAFRetriever` и `build_tools`) —
основной для LangChain: нет ни транспорта, ни второго процесса, и — главное для
тестов — он не запускает переиндексацию по своей воле (`watch=False`). MCP —
второй путь к тем же 74 инструментам, когда нужен отдельный процесс (иные
зависимости) или другой клиент. HTTP API не пишется: его появление означало бы
вторую реализацию поиска, исключений и провенанса.

**Найденные дефекты совместимости** (не наши, но влияют на выбор версий):

* `langchain.mcp` доступен только с дополнением `langchain[mcp]` и выдаёт
  `LangChainBetaWarning`; пример из статей с `MultiServerMCPClient` в этой среде
  не работает вовсе — см. следующий пункт.
* `langchain-mcp-adapters` 0.3.2 объявляет `mcp>=1.24,<2`, но импортирует
  `RequestContext` из `mcp.shared.context`, которого нет ни в 1.30.0, ни в 2.3.0:
  вместе с `langchain[mcp]` (mcp 2.x) пакет просто не импортируется. Два MCP-пути
  в одном окружении не живут.
* MCP-сервер RAGRAF не имеет переключателя сторожа: первый вызов после правки
  кода длится столько же, сколько переиндексация (замер: ≈ 290 с на 1058 файлах).
  Прямой путь этого не делает: свежесть возвращается полем `stale` и
  инструментом `ragraf_freshness`.
