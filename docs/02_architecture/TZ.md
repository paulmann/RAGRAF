# Техническое задание: RAGRAF

**Версия:** 1.0 · **Дата:** 2026-10-04 · **Проект:** `RAGRAF`
**Основание:** `docs/00_plan/PLAN.md`, `docs/01_research/SPEC_INPUT.md`, `docs/02_architecture/ARCHITECTURE.md`
**Заказчик:** владелец AutoClaw. **Исполнитель:** AutoClaw.
**Решения заказчика, зафиксированные 2026-10-04:** JVM (JDK 19 + Joern) разрешена · пилот `revoap.com` · эмбеддинги `paraphrase-multilingual-MiniLM-L12-v2` · релиз 1 — только PHP.

---

## 1. Назначение и цель

Система RAGRAF создаёт и сопровождает **вспомогательную базу знаний о коде** (граф + символы + вектор + лексика), чтобы LLM-агент при разработке и доработке ПО **не изучал репозиторий вслепую**, а получал проверяемые ответы: где лежит, кто вызывает, что сломается, как сделано в похожем месте.

**Цель по трём фазам жизненного цикла:**
1. перед доработкой — индексация кода;
2. во время доработки — ответы агента из базы и **накопление различий** между базой и кодом в отдельном журнале;
3. после доработки — переиндексация, приводящая базу в соответствие с кодом.

**Ключевое требование, ради которого делается журнал:** в процессе накопления различий агент не должен делать выводов по устаревшим данным, **не зная** об этом.

## 3. Терминология

| Термин | Значение |
|---|---|
| **Корпус** | набор файлов проекта, подлежащих индексации, по правилам `config/project.yaml` |
| **`INDEX_REV`** | именованная иммутабельная ревизия индекса (`rev-0007`) |
| **Факт** | узел или ребро графа, содержащий `evidence` (`path:line`) и `confidence` |
| **`stated` / `derived`** | ребро, доказанное анализатором / выведенное эвристикой |
| **Ledger** | append-only журнал различий между индексом и кодом |
| **`stale`** | факт, затронутый записью ledger и потому не гарантированно актуальный |
| **Деградация** | режим ревизии без CPG (`capability: degraded`) |
| **Замер** | процедура из `ACCEPTANCE.md`, дающая число |

### 4.3 Журнал расхождений и ревизий

| ID | Требование | Критерий приёмки | Проверка |
|---|---|---|---|
| **ФТ-24** | Индекс неизменен в пределах ревизии: во время доработки операции чтения не меняют `graph.sqlite`/`lexvec.sqlite` | После 200 операций чтения хэши файлов хранилищ не изменились | Тест M5-T1 |
| **ФТ-25** | Обнаружение дельт доступно 5 способами: `hook:session-start`, `compare`, `git-diff`, `db-schema-diff`, `manual` | Каждый способ создаёт корректную запись `drift_entry` | Тест M5-T2 |
| **ФТ-26** | Ledger append-only: нет операций удаления/обновления записей | Попытка удаления записи невозможна через фасад; схема не содержит `DELETE`-путей | Тест M5-T3 |
| **ФТ-27** | Дедупликация: повторное обнаружение той же дельты не задваивает журнал | Двойной запуск `compare` без правок → число записей не изменилось | Тест M5-T4 |
| **ФТ-28** | Помечивание `stale`: при непустом ledger ответы по затронутым путям несут `stale_warnings` | Для 20 затронутых путей все ответы, их касающиеся, имеют предупреждение | Замер M5 |
| **ФТ-29** | Отдельный вид записи `slice_boundary` при выносе кода в функцию | Правка extract-method даёт запись `slice_boundary` **и** `modify` | Тест M5-T5 |
| **ФТ-30** | Обнаружение изменения схемы БД: появившаяся/удалённая колонка → запись `schema_change` | Миграция на стенде создаёт запись с именем таблицы и колонки | Тест M5-T6 |
| **ФТ-31** | `live_read` показывает, чем файл отличается от индекса | Фрагменты, изменённые после ревизии, выделены; `provenance: mixed` | Тест M5-T7 |
| **ФТ-32** | `reindex --commit` создаёт новую ревизию, архивирует ledger, очищает `stale_edge` | После команды: новая `INDEX_REV`, ledger пуст, файл архива создан | Тест M5-T8 |
| **ФТ-33** | Архив переиндексации — человекочитаемый отчёт «что изменилось в знаниях» | Отчёт содержит разделы: изменения по файлам, что устарело, границы срезов | Тест M5-T9 |
| **ФТ-34** | История ревизий сохраняется: `rev_history` и `drift_archive` не удаляются при ротации | После 5 переиндексаций при `retain_revs: 3` — 5 записей в истории, 2 ротированные ревизии удалены из хранилищ | Тест M5-T10 |
| **ФТ-35** | Запись дельты — только через фасад, не агентом напрямую | Прямая запись в `control.sqlite` не является штатным путём; операции записи не выставляются наружу | Ревизия интерфейса + тест |
| **ФТ-36** | `drift_ack` не удаляет запись, а дописывает признание | После `drift_ack` запись присутствует с заполненным `ack` | Тест M5-T11 |

## 8. Риски и меры

| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| `php2cpg` даёт неполный CPG на реальном коде | Средняя | Потеря `slice`/`flow` | Режим `degraded` предусмотрен; метрика покрытия вызовов выявит потерю; при провале — `slice` через SCIP/собственные правила |
| Полная сборка CPG не укладывается в 15 мин | Средняя | Ломает НФТ-2 | Сужение CPG: только изменённые файлы + вызывающие их (решение по замеру) |
| Joern требует больше памяти, чем доступно | Низкая | Сбой сборки | Лимит `-Xmx` в конфиге; при нехватке — деградация, не падение (НФТ-8) |
| Работа агента оставляет индекс «протухшим» незаметно | Средняя | Ложные выводы | ФТ-24, ФТ-28, ФТ-32: индекс неизменен, факты помечаются, переиндексация обязательна |
| Ложные рёбра от эвристик PHP портят ответы | Высокая | Снижение доверия | Разделение `stated`/`derived` (ФТ-4, ФТ-18), калибровка достоверности на 20 примерах |
| `sqlite-vec` меняет API (pre-v1) | Средняя | Ломает векторный слой | Изоляция за модулем; переход на `qdrant-client` по порогу (замер) |
| Секреты попадают в индекс | Средняя | Утечка | ФТ-39/ФТ-40, список исключений, тест на образцах |
| Рост ledger до нечитаемого объёма | Средняя | Вред от накопления (AdaRepair-Mem: «больше памяти ≠ лучше») | Архивация при реиндексации, дедупликация (ФТ-27), приоритизация по затронутым путям |
| Ротация ревизий удаляет нужную историю | Низкая | Потеря данных | История и архивы не удаляются (ФТ-34) |

## 10. Ограничения и оговорки

1. **Проценты сжатия из статьи-источника (68–70% и 90,93%) в ТЗ не используются** — не подтверждены первоисточником.
2. **Ссылка на LeanGuard не используется** — работа по этому названию не найдена.
3. **Все опубликованные ориентиры получены на C/C++ и на поиске уязвимостей**; наши метрики снимаются на PHP и на задачах доработки, поэтому чужие числа служат только ориентиром порядка величины.
4. **Без CPG (режим деградации) система честно сообщает об этом** и не отдаёт `slice`/`flow`; требования к ним выполнены при `capability: full`.
5. **Пороги достоверности требуют калибровки** (разброс в литературе — в 3 раза между корпусами); до калибровки используются стартовые значения из архитектуры §5.2.
6. **Лицензионные ограничения:** CodeQL в стек не входит; Joern — Apache-2.0; `sqlite-vec`, `fastembed`, `tree-sitter`, SCIP-инструменты — MIT/Apache-2.0; версии фиксируются (НФТ-7).
