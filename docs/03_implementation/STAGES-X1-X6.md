## 2. X1 — происхождение: от какого документа и до какого момента факт верен

Задача: у факта появилась не только ссылка `файл:строка`, но и **время
действия** и **цепочка вывода** — из какого документа факт получен и на что он
сам влияет. Без этого нельзя ответить «что было верно на 1 октября» и «что
сломается, если поправить этот абзац».

| что | где |
|---|---|
| разбор интервала действия (`с 12.03.2026`, `до 2026-06-01`, `бессрочно`) | `src/ragraf/provenance.py:275` |
| запись слоя происхождения в лексическое хранилище | `src/ragraf/provenance.py:360` |
| сборка производных фактов из документов | `src/ragraf/provenance.py:473` |
| обратный обход: на что влияет факт | `src/ragraf/provenance.py:725` |
| операция «что было верно на дату» | `src/ragraf/facade.py:5875` |
| операция «от чего зависит утверждение» | `src/ragraf/facade.py:5914` |
| набор проверок (42 свойства) | `tests/test_provenance.py` |
| документ возможности | `docs/03_implementation/DOC-PROVENANCE.md` |

Решения, которые стоит помнить:

- **Второго хранилища нет.** Слой происхождения живёт в существующем
  лексическом хранилище корпуса, а не в отдельной SQLite: два хранилища фактов
  расходятся так же, как любые две копии.
- **Интервал не догадка.** Если интервал не разобран, факт не получает
  «примерно» — он получает названную причину, и это видно в ответе.
- **Производный факт без источника не выдаётся.** Цепочка обрывается явно, а не
  подменяется пустой ссылкой.

Числа этапа: операции фасада 68 → **70**, инструменты MCP 75 → **77**,
возможности 17 → **18** (Pro 12 → 13). Источник — `docs/plans/X1-REPORT-2026-11-09.md`.

## 3. X2 — одно место для чисел: сколько операций, инструментов, возможностей

Задача: прекратить расхождение «в документах одно число, в коде другое». До
этапа в проекте одновременно жили 54 / 59 / 61 / 66 операции при фактических 60,
и каждый документ считал по-своему.

| что | где |
|---|---|
| счёт поверхности из кода (AST, а не регулярка) | `src/ragraf/surface.py:279` |
| описание операций: параметры и ключи ответа | `src/ragraf/surface.py:134` |
| отпечаток состава (без ревизии) | `src/ragraf/surface.py:64` |
| генератор подстановки чисел в документы | `tools/surface_gen.py:99` |
| русские формы числительных выбирает код | `tools/surface_gen.py:70` |
| подстановочные слоты для шаблонов | `tools/surface_gen.py:88` |
| шаблоны восьми документов и маркеры | `tools/surface_templates.json` |
| артефакт с числами и отпечатком | `docs/surface.json` |
| как это устроено | `docs/03_implementation/SURFACE-NUMBERS.md` |
| набор проверок (76 свойств) | `tests/test_documented_numbers.py` |

Решения:

- **Числа — данные, а не текст.** Документы содержат маркеры
  `<!-- surface:slot -->`, а значения подставляет генератор; править число
  руками в тексте бессмысленно — его перезапишут.
- **Формы числительных считает код** (слот `{ops_phrase}` / `{tools_phrase}`):
  русское «74 операции» против «81 инструмент» — не украшение, а часть
  утверждения.
- **Порядок обязателен:** `surface_gen --write` → `registry_line --write` →
  `surface_gen --check`. Средний шаг пересчитывает хэши переводов в таблице
  источников; без него гейт поставки красный.

Числа этапа не менялись (70 / 77 / 18): этап добавил счёт, а не операции.
Отпечаток поверхности `e3658b9709dc…`. Источник — `docs/plans/X2-REPORT-2026-11-09.md`.

## 4. X3 — якоря замысла: сверка объявленного контракта с вычисленным графом

Задача: к внешнему YAML-манифесту проекта добавить **якоря в комментариях**
(`START_MODULE_CONTRACT`, `START_CONTRACT`, `MODULE_MAP`), чтобы расхождение
«задумано — написано» находилось и без манифеста, а конфликт двух источников
был виден как находка, а не как тишина.

| что | где |
|---|---|
| выбор файлов-кандидатов для чтения якорей | `src/ragraf/anchors.py:68` |
| разбор якорей из текста файла | `src/ragraf/anchors.py:80` |
| закрытие открытого якоря по номеру строки | `src/ragraf/anchors.py:126` |
| загрузка якорей всего корпуса | `src/ragraf/anchors.py:277` |
| закрытый список видов дрейфа (11 видов) | `src/ragraf/contracts.py:69` |
| сверка манифеста, якорей и графа | `src/ragraf/contracts.py:698` |
| операция с полем `source` (manifest / anchors / both) | `src/ragraf/facade.py:1612` |
| набор проверок (35 свойств) | `tests/test_contracts_anchors.py` |
| документ возможности | `docs/03_implementation/CONTRACT-ANCHORS.md` |

Решения:

- **Манифест главнее якоря.** Конфликт не разрешается «в пользу более
  свежего»: он выдаётся находкой `anchor_conflict` с двумя адресами.
- **Список видов дрейфа закрыт** (6 → 11 видов). Вид вне списка — дефект кода,
  а не «новая категория»; иначе отчёт тихо теряет находки.
- **У каждой находки адрес.** Расхождение без `файл:строка` — не находка.

Числа этапа: 70 / 77 / 18 без изменений (новой операции нет, у существующей
появилось поле). Отпечаток `87700b2c42be…`. Источник —
`docs/plans/X3-REPORT-2026-11-09.md`.

## 5. X4 — поведение под замером: кейсы и парные прогоны

Задача: измерять не «сколько нашлось», а **правильно ли ответил** продукт.
Появились фиксированные кейсы (вопрос → ожидаемая находка), прогон набора и
сравнение двух прогонов между собой.

| что | где |
|---|---|
| нормализация кейса | `src/ragraf/quality_cases.py:140` |
| загрузка кейсов корпуса | `src/ragraf/quality_cases.py:174` |
| загрузка бенчмарка (ожидания машинно-зависимы) | `src/ragraf/quality_cases.py:247` |
| оценка одного кейса | `src/ragraf/quality_cases.py:366` |
| оценка набора | `src/ragraf/quality_cases.py:451` |
| сравнение двух прогонов | `src/ragraf/quality_cases.py:483` |
| блок `cases` в отчёте качества | `src/ragraf/quality_loop.py:216` |
| парный прогон `quality_pair` | `src/ragraf/quality_loop.py:711` |
| чтение решений гейта (не второй журнал) | `src/ragraf/gate.py:413` |
| запись решения гейта | `src/ragraf/gate.py:432` |
| операция `quality_pair` | `src/ragraf/facade.py:8666` |
| инструмент `ragraf_quality_pair` | `src/ragraf/mcp_server.py:715` |
| набор проверок (49 свойств) | `tests/test_quality_cases.py` |
| документ возможности | `docs/03_implementation/QUALITY-CASES.md` |

Решения:

- **`quality_pair` — не `quality_diff`.** `quality_diff` по-прежнему
  отказывается выносить вердикт между ревизиями; парный прогон отвечает на
  другой вопрос — «на тех же кейсах стало лучше или хуже». Разница названа в
  самом ответе, а не подразумевается.
- **Кейсы не входят в отпечаток индекса.** Отпечаток описывает индекс, а не
  вопрос, который ему задают.
- **Ожидания бенчмарка включаются осознанно** (`machine: true`): чужой
  `bench/tasks.yaml` описывает другой корпус, и молчаливое применение дало бы
  ложные провалы.

Числа этапа: операции 70 → **71**, инструменты 77 → **78**, возможности 18 без
изменений (расширена `quality-loop`). Отпечаток `49b4f6ee39ba…`. Источник —
`docs/plans/X4-REPORT-2026-11-09.md`.

## 6. X5 — осмотр корпуса до индексации и единый текст отказа

Задача: до построения индекса ответить, **чего он будет стоить и что не
покроется** (сгенерированные файлы, динамические места, миграции), и свести все
отказы продукта к одному тексту с одним следующим шагом.

| что | где |
|---|---|
| признаки сгенерированного файла | `src/ragraf/preflight.py:47` |
| шаблоны динамических мест по языкам | `src/ragraf/preflight.py:63` |
| оценка погрешности по выборке | `src/ragraf/preflight.py:189` |
| осмотр корпуса (ничего не создаёт) | `src/ragraf/preflight.py:348` |
| предел чтения файлов на прогон | `src/ragraf/preflight.py:42` |
| закрытый список видов отказа (9 видов) | `src/ragraf/util.py:540` |
| единый следующий шаг отказа | `src/ragraf/util.py:586` |
| операция `preflight` | `src/ragraf/facade.py:1726` |
| подсказка «в каком конфиге дело» | `src/ragraf/facade.py:7561` |
| отказ «индекса нет» | `src/ragraf/facade.py:7570` |
| инструмент `ragraf_preflight` | `src/ragraf/mcp_server.py:654` |
| флаг выборки в командной строке | `src/ragraf/cli.py:2674` |
| набор проверок (34 свойства) | `tests/test_preflight.py` |
| документ возможности | `docs/03_implementation/PREFLIGHT.md` |

Решения:

- **Осмотр ничего не создаёт.** Проверено снимком каталога: `preflight` не
  заводит ни индекса, ни конфига — иначе «осмотр» был бы скрытым действием.
- **Отказ — закрытый список из девяти видов.** Вид вне списка поднимает
  исключение: опечатка не должна давать пустой совет.
- **Совет — одна команда.** `problem` / `why` / `action` / `action_note` /
  `possible`: отказ, из которого нельзя выйти одной командой, бесполезен.

Числа этапа: операции 71 → **72**, инструменты 78 → **79**, возможности 18 → **19**

## 7. X6 — пиннинг подписи операций

Задача: изменение контракта операции (параметр с умолчанием, ключи ответа, имя)
должно быть видно, а не выглядеть как «индекс врёт».

| что | где |
|---|---|
| каноническая запись описания для хеша | `src/ragraf/pin.py:86` |
| описание операции: параметры и ключи ответа | `src/ragraf/pin.py:96` |
| хеши всех операций (описание берётся из `surface`) | `src/ragraf/pin.py:120` |
| подтверждение пина человеком | `src/ragraf/pin.py:195` |
| наблюдение хеша на вызове и `pin_mismatch` | `src/ragraf/pin.py:229` |
| `pin_break` — только после расхождения | `src/ragraf/pin.py:266` |
| состояние пинов, расхождения, события | `src/ragraf/pin.py:321` |
| догоняющая миграция колонки `observed_hash` | `src/ragraf/telemetry.py:347` |
| операция `contract_pin_status` | `src/ragraf/facade.py:1788` |
| операция `contract_pin_approve` | `src/ragraf/facade.py:1832` |
| разбор новых операций в командной строке | `src/ragraf/cli.py:1059` |
| инструмент `ragraf_contract_pin_status` | `src/ragraf/mcp_server.py:612` |
| инструмент `ragraf_contract_pin_approve` | `src/ragraf/mcp_server.py:633` |
| набор проверок (30 свойств) | `tests/test_contract_pin.py` |
| документ возможности | `docs/03_implementation/CONTRACT-PIN.md` |

Решения:

- **Описание одно.** Хеш считается по `surface.ops_of`; второй реализации
  описаний нет — две разошлись бы, и пин ловил бы расхождение копий, а не
  контракта.
- **Автоподтверждения нет.** Пин ставит человек и с автором: самоподпись
  скрывала бы ровно то, ради чего пин нужен.
- **Событие пишется один раз на пару «операция + хеш».** Иначе один сломанный
  клиент забил бы журнал тысячей одинаковых записей.

Числа этапа: операции 72 → **74**, инструменты 79 → **81**, возможности 19 → **20**
(Pro 14 без изменений, Enterprise 19 → 20). Отпечаток `f4bedb7912cd…`. Источник —
[`X6-REPORT-2026-11-09.md`](../plans/X6-REPORT-2026-11-09.md).

## 10. Что осталось открытым

- **Пин на живом корпусе не поставлен.** `contract_pin_status` показывает
  0 пинов и 74 неподтверждённых операции. Это решение владельца: пин означает
  «это описание я принимаю», и выдать за него самоподпись этап не имеет права.
- **Поведение пин не описывает.** Хеш описывает объявление операции, а не то,
  что она делает; изменённый ответ при том же объявлении не ловится, и это
  названо в ответе операции, а не умолчано.
- **Блоки плана, закрытые частично,** перечислены в плане с причиной; сведение
  «блок → поставка → проверка» — задача этапа X7.
