# TypeScript, JavaScript и Astro: что индекс считает фактом

Документ слоя. Появился после внешнего разбора 22.11.2026: на проекте заказчика
(TypeScript + Astro) анализ кода давал неверные ответы, а `dead_code` мог
подтолкнуть удалить живой файл. Здесь — как устроены разбор, связывание вызовов
и граница между «связи нет» и «связь не построена».

Замеры сделаны на песочном корпусе TypeScript + Astro (3 `.ts` + `page.astro`),
проверки — `tests/test_client_report.py` и `tests/test_drift_restore.py`.

## 1. Разбор: что даёт символ

| Конструкция | Символ | Где реализовано |
|---|---|---|
| `function f() {}` | `function` | `PROFILES["typescript"].functions` |
| `const f = () => {}` | `function` | `function_values` (`arrow_function`) |
| `const f = function () {}` | `function` | `function_values` (`function_expression`) |
| `const g = function* () {}` | `function` | `function_values` (`generator_function`) |
| `const port = 8080` | нет символа | значение не функциональное |
| `type Id = string \| number` | `type_alias` | `type_aliases` |
| `class C {}`, `interface I {}` | `class`, `interface` | те же профили |

Два поля вместо одного (`function_values`, `type_aliases`) появились потому, что
запись «`variable_declarator` — это функция» превратила бы любую константу в
функцию: имя есть, вызовов нет, и `dead_code` получил бы ложную цель.

Разметка файла `.astro` в символы не превращается: разбираются frontmatter между
`---` и каждый блок `<script>`, остальное маскируется **с сохранением переводов
строк** — иначе `path:line` уехал бы на число строк разметки.

## 2. Связывание вызовов по импорту

Порядок: извлекатель создаёт заглушку `@ext:<name>` для вызова, который не
нашёлся в файле; затем пост-проход индексатора (`Indexer._resolve_js_imports`)
читает строки импорта и заменяет заглушку ребром на определение.

- `evidence_kind="import"`, `provenance="derived"`, уверенность **0.9**;
- адрес доказательства (`path:line`) берётся у заменяемой заглушки — это ровно
  то место, где вызов записан; до правки в ответ уходило `app.ts:None`;
- пакетные спецификаторы (`react`, `@scope/pkg`) не связываются: файла нет;
- алиасы `tsconfig.paths` **не поддержаны** — названо, не сделано;
- `.astro` входит в набор расширений резолвера: импорты в страницах живут там же.

Ребро `imports` (файл → файл) строится тем же проходом. Оно же служит входящей
ссылкой для `analysis.graph_refs`, поэтому импортируемый файл не попадает в
`dead_code`.

## 3. `dead_code`: приговор и недоказанное

Ответ разделён на две части:

- `files` — приговор: ссылок нет ни одной (в том числе нет входящего `imports`);
- `unproven` — файлы, где есть вызовы с `evidence_kind="external_call"`:
  связывание не удалось, и объявлять файл мёртвым нельзя. В `limits` и
  `extra["unproven_count"]` видно, сколько таких случаев.

Правило: **«связи нет» ≠ «связь не построена»**. Второе — долг инструмента, а не
факт о коде, и удалять по нему нельзя.

## 4. Формат `astro` в реестре

`formats.py` — единственный реестр: `DataFormat("astro", "Astro", "code",
(".astro",), structure="tree", engine="typescript", note=…)`. Из него строится
настройка `index_formats`, отбор файлов в `corpus.scan` (счётчик
`skipped_formats`) и вкладка «Форматы» в панели. Второй список расширений
заводить нельзя: расхождение не даёт ошибки, формат просто перестаёт
управляться из интерфейса.

Набор языков разбора (`Indexer._parse_languages`) — это `{"php","css","html",
"astro"} | set(PROFILES)`: `astro` не профиль грамматики, а собственный
извлекатель, и без этой строки файл шёл текстовым путём (замер: 4 файла в
корпусе, узлов 8 — страница дала только узел файла).

## 5. Честность состояния

- `index_status` разделяет `vector_library` (библиотека эмбеддингов есть),
  `vectors_indexed` (сколько векторов в ревизии) и `vector_available` (оба
  условия). `vector_note` называет причину: «векторов в ревизии нет: индекс
  собран с `--no-vectors`» или «библиотека эмбеддингов недоступна».
- `db.enabled: false` в конфиге корпуса спрашивается ПЕРВЫМ и в сборе, и в
  чтении: шесть операций слоя баз отказывают с причиной, а отчёт индексации
  печатает её текстом.
- Каталог индекса задан корнем проекта. При недоступном каталоге — код 3 и
  причина (`util.dir_blocker`), а не `OperationalError: ... не существует`.
