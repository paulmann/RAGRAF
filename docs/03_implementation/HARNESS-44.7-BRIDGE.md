# HARNESS 44.7.0: почему гейт хуков замолчал и что теперь делает RAGRAF

Дата: 02.11.2026. Все числа и версии ниже — замеры на этой машине, не пересказ
документации. Где утверждение опирается на вывод команды, команда названа.

## 1. Что сломалось (три независимые причины)

| # | Причина | Как измерено |
|---|---|---|
| 1 | Моста хуков нет в сборке клиента | в `resources/app.asar` (182 766 714 Б, 18 234 файла) нет ни `dsh-hooks-claude-code`, ни `dsh-hook-protocol`: поиск по заголовку архива даёт 0 совпадений. Запись `hooks-shared` в профиле осталась и указывает в пустоту |
| 2 | Хуки не вызываются | в 40 последних стенограммах (`session.v4.jsonl.zstd`) 345 исторических `hook/invoked`, последний — **23.10.2026 12:31:32**; в текущем сеансе — ни одного |
| 3 | Команда хука не разбирается PowerShell | прежняя форма `"…python.exe" "…harness_gate.py" pre-tool`: `pwsh -Command` → `ParserError: Unexpected token '-V'`, код 1. Воспроизведено и закреплено проверкой `parse_only` |

Плюс два собственных дефекта скрипта хука:

* вывод падал `UnicodeEncodeError` при `PYTHONIOENCODING=cp1252` (окружение клиента), обработчик по правилу fail-open писал «вызов разрешён» и возвращал 0 — то есть гейт молча превращался в разрешение;
* `DEFAULT_MODE = "ask"` в `tools/harness_gate.py` против `DEFAULT_MODE = "warn"` в `src/ragraf/gate.py`: текст SessionStart расходился с фактическим поведением.

И один дефект установщика, найденный по ходу: `yaml.safe_load` не разбирает тег
`!!js` (`dshHomePath('cache/session-search.db')`), который стоит в живом профиле.
Из-за этого `install_harness_gate.py` объявлял профиль нечитаемым («записей
гейта: нет») и добавлял ВТОРОЙ блок.

## 2. Что сделано в RAGRAF

### 2.1 `src/ragraf/harness.py` (новый модуль)

| Функция | Что даёт |
|---|---|
| `install_root()`, `app_version()`, `runtime_version()` | версия приложения (`44.7.0` из файла `version`) и версия пакетов (`0.2.1-rc.5` из `app.asar`) читаются с диска; заголовок архива разбирается один раз на процесс |
| `bundled(root, package)` | есть ли пакет В СБОРКЕ (по заголовку asar), а не «вообще в npm» |
| `state(profile)` | отчёт: мост и протокол в профиле и в сборке, запись в патче, файл хуков, последнее `hook/invoked`, список действий. Где проверить нельзя — поле `skipped` с причиной, а не догадка |
| `install_bridge(profile, dry_run)` | установка родной командой `dsh plugin --profile <p> add …`, с копиями `package.json`/`pnpm-lock.yaml`/`cordis.patch.yml` и откатом при отказе клиента |
| `profile_store_dir(profile)` | хранилище pnpm, из которого собран `node_modules` профиля (см. §3) |
| `hook_events()` | последнее `hook/invoked` по стенограммам; без `compression.zstd` (Python 3.13) — честное «не проверено» |
| `safe_command()`, `split_command()`, `parse_only()`, `verify_command()` | сборка команды без кавычек, разбор парсером PowerShell без выполнения, прогон в PowerShell и `cmd /c` |

### 2.2 `tools/harness_gate.py`

* вывод пишется **байтами UTF-8** в `sys.stdout.buffer`, JSON кодируется с `ensure_ascii=True` — при любой кодировке канала ответ остаётся валидным JSON;
* режим берётся из ядра (`gate.DEFAULT_MODE`), своей константы больше нет;
* новая стадия `selftest` — проверка связки без побочных эффектов (не пишет сеанс в состояние гейта).

### 2.3 `tools/install_harness_gate.py`

Установка стала четырёхшаговой и печатает каждый шаг:

1. **пакеты профиля** — если моста нет: `dsh plugin --profile desktop add @deepseek-ai/dsh-hooks-claude-code@<версия рантайма>`; протокол `@deepseek-ai/dsh-hook-protocol@<версия>` добавляется отдельно, потому что его в сборке тоже нет, а мост его импортирует;
2. **команды** — `harness/hooks.json` собирается заново в форме без кавычек, затем свод `harness/all-hooks.json` пересобирается штатным `tools/merge_hooks.py`;
3. **проверка** — каждая команда разбирается парсером PowerShell (именно там был `ParserError`), цепочка целиком проверяется стадией `selftest` в PowerShell и `cmd /c`; пока проверка не прошла, профиль не меняется;
4. **патч профиля** — идемпотентная запись `hooks-shared` с `configPath` на свод, копия файла, откат при любом расхождении (YAML не разобрался, запись не появилась, чужие хуки потеряны).

Разбор патча теперь понимает тег `!!js` (см. §1).

### 2.4 `tools/merge_hooks.py`

Свод переписывает команды **всех** источников в форму без кавычек: пути с
пробелами сокращаются до 8.3, остальное не меняется. Это чинит не только гейт
RAGRAF, но и хуки xerj/bsg — у них была та же ошибка:

```
было:  "C:\Program Files\PowerShell\7\pwsh.exe" -NoLogo … -File …\session-hook.ps1
стало: C:\PROGRA~1\POWERS~1\7\pwsh.exe -NoLogo … -File C:\work\tools\session-hook.ps1
```

## 3. Ловушка, которая ждала на живом профиле

Первая установка упала:

```
pnpm now wants to use the store at "C:\Users\…\.pnpm\store\v11" …
(this error may happen if the node_modules was installed with a different major version of pnpm)
```

`node_modules` профиля собран pnpm **11.7.0** с хранилищем
`C:\Users\…\AppData\Local\pnpm\store\v11` (записано в `.modules.yaml`), а
встроенный в HARNESS pnpm **11.28.5** по умолчанию идёт в
`…\.pnpm\store\v11` и отказывается связывать. Поэтому установщик читает
`storeDir` из профиля и передаёт его явно: `--config.store-dir=<путь>`.
С этим флагом установка проходит за 0,8 с.

## 6. Что осталось сделать человеку

**Перезапустить HARNESS.** Конфиг хуков читается один раз при старте процесса,
поэтому до перезапуска мост не смонтируется. После перезапуска:

```powershell
python tools/install_harness_gate.py --check
```

Строка «вызовы хуков» должна показать свежее время вместо `2026-10-23 12:31:32`.
Если время не изменилось — мост не поднялся; тогда смотреть журнал операции
клиента `.dsh\profiles\desktop\.plugin-manager\logs\` и отчёт панели, а не
править YAML руками.

## 7. Вопрос, который был открыт и снят замером

Разрешает ли загрузчик клиента peer-зависимости моста (`@deepseek-ai/dsh-llm`,
`dsh-agent`, `dsh-session`, `cordis`) из собственной сборки — **да**. Пробный
плагин в профиле импортировал `dsh-llm` (66 экспортов) и сам мост (4 экспорта);

## 9. Вторая итерация (02.11.2026, вечер): что показал разбор

После установки и перезапуска клиента (процесс `DeepSeek Harness.exe` стартовал
в 17:10:28, пакеты стояли с 14:09) хуки сначала молчали, и `--check` показывал
прежнее время. Разбор шёл тремя замерами в песочных профилях (`DSH_HOME` в
`%TEMP%`, ключ модели брался из `refs.DEEPSEEK_API_KEY` живого хранилища и
передавался переменной окружения, в вывод не попадал).

**1. Плагин из профиля монтируется.** Пробный плагин в `node_modules` профиля
без единой зависимости от `@deepseek-ai` вошёл в исполнение, а динамический
импорт рядом с ним разрешил `@deepseek-ai/dsh-llm` (**66 экспортов**) и сам мост
(**4 экспорта**). То есть peer-зависимости моста загрузчик даёт из своей сборки —
опасение из §7 снято замером.

**2. Наш файл хуков принимается как есть.** С `configPath` на живой
`harness/all-hooks.json` в песочном профиле появились `hook/invoked` и
`hook/result` для `UserPromptSubmit` и `Stop`. Значит разбор конфигурации
(ключи `_readme`, `sources`, матчер `mcp__ragraf__.*`) мост не отвергает.

**3. Главная находка: песочная оболочка не может запустить процесс хука.**
В песочном профиле **любая** команда хука завершалась кодом **3221225794**
(`0xC0000142`, `STATUS_DLL_INIT_FAILED`) — включая `cmd.exe /c echo …`. Замена
песочной оболочки на обычную (`- id: pwsh-sandbox disabled: true` плюс
`@deepseek-ai/dsh-pwsh-local`) дала **код 0**, и гейт сработал: в рассуждении
модели появилось «RAGRAF: гейт использования индекса активен (режим warn)», то
есть контекст SessionStart дошёл.

Для этого в `src/ragraf/harness.py` добавлены `hook_verdict()` (различает
`not_invoked` / `spawn_failed` / `timeout` / `command_error` / `ok` по измеренным
кодам и длительности) и `apply_plain_shell()` с флагом
`install_harness_gate.py --plain-shell` (обратный ход — `--sandbox-shell`).
Переключатель меняет настройку безопасности клиента, поэтому по умолчанию НЕ
включается: `--check` только называет причину.

**4. В живом клиенте хуки работают.** В 17:23–17:31 в живой стенограмме
`session-6e4263fd…` появились `hook/invoked`/`hook/result` с `exitCode 0` и
`decision: allow` (это ответ нашего гейта), а `catalog/gate_state.json` записал
сеанс `session-4b95f403…` с `cwd=C:\AutoClaw\RAGRAF` и 8 новых решений. Значит
десктопная сборка запускает хуки не в песочной оболочке (в отличие от песочного
headless-профиля) — расхождение измерено, а не предположено.

**5. Таймауты были следствием нагрузки.** Четыре вызова упёрлись в `timeout: 60`
(`exitCode 1`, `decision: pass`, `durationMs ≈ 60 000`). Сам гейт отвечает за
**0,13 с** (`selftest` 0,09, `session-start` 0,10, `pre-tool` 0,13): таймауты
пришлись на минуты, когда на машине крутились мои же песочные прогоны. Поэтому
`hook_verdict()` теперь отделяет `timeout` от ошибки команды.

**Итог измерений:** установка моста + перезапуск = рабочий гейт. Проверка:
`install_harness_gate.py --check` показывает `выполнение: ok` и свежее время
`вызовов хуков`; в `gate_state.json` появляется сеанс с вашим `session_id`.
