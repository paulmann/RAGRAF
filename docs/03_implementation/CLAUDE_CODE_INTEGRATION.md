## 1. Как это устроено

Интеграция состоит из **четырёх независимых частей**, и каждая проверяется
отдельно. Сервер без правил — это «инструмент есть, пользоваться не
обязательно»; правила без хука — «написано, но не проверено»; хук без метки
задачи — «обращения есть, а к какой задаче относятся, неизвестно».

| Часть | Где у клиента | Что даёт |
|---|---|---|
| MCP-сервер `ragraf` | `~/.claude.json`, ключ `mcpServers` (область `user`) | инструменты `mcp__ragraf__ragraf_*` во всех проектах |
| Хуки (4 события) | `~/.claude/settings.json`, ключ `hooks` | факты корпуса в начале сеанса, метка задачи, гейт перед файловым поиском, отчёт в конце хода |
| Правила | `~/.claude/CLAUDE.md`, блок между маркерами `== RAGRAF` | порядок «сначала индекс, потом файлы» и запреты |
| Навык | `~/.claude/skills/ragraf-core`, `ragraf-secrets` | справочник операций и работы с секретами |

**Транспорт — MCP stdio.** Тот же сервер, что у AutoClaw и HARNESS
(`tools/ragraf-mcp.py`), запускается интерпретатором из `.venv` проекта: клиент
передаёт дочернему процессу урезанное окружение, и зависимости RAGRAF
(`fastembed`, `PyYAML`, `sqlite_vec`, `tree_sitter`, `ijson`) достижимы только
так. Имя сервера в конфигурации — `ragraf`; от него зависят имена инструментов:
`mcp__ragraf__ragraf_search`, `mcp__ragraf__ragraf_ensure` и так далее.

**Один сервер на все проекты.** Держать по серверу на проект значило бы держать
по копии индекса в памяти на каждый. Корпус определяется по рабочему каталогу
процесса через реестр разработок; если каталог чужой — операция `use_project`
переключает корпус, а `context` называет, какой корпус выбран и на каком
основании.

**Хуки — тот же файл, что у HARNESS.** `tools/harness_gate.py` читает JSON
протокола хуков со stdin и пишет ответ в `hookSpecificOutput`; протокол у
Claude Code и у моста DSH общий, поэтому логика живёт в одном месте, а не в
двух копиях. В этой сессии в него добавлены две вещи, нужные именно клиенту:
факты корпуса в `SessionStart` и метка задачи в `UserPromptSubmit`.

| Событие | Стадия скрипта | Что делает |
|---|---|---|
| `SessionStart` | `session-start` | открывает маркер сеанса и кладёт в контекст строку: имя корпуса, ревизия, свеж ли индекс |
| `UserPromptSubmit` | `prompt` | первый запрос сеанса становится меткой задачи; последующие её не меняют |
| `PreToolUse` | `pre-tool` | `allow`/`ask`/`deny` перед файловым поиском и чтением; режим по умолчанию `warn` |
| `Stop` | `stop` | строка отчёта по задаче: обращения, факты, доля со ссылкой `файл:строка` |

## 2. Что измерено на этой машине

| Что | Значение | Как проверено |
|---|---|---|
| версия клиента | `2.1.316 (Claude Code)` | `claude --version` |
| запись MCP области `user` | `~/.claude.json` → `mcpServers.ragraf` | `claude mcp add-json --scope user`, затем чтение файла |
| сервер поднимается | `Status: √ Connected` | `claude mcp get ragraf` (команда сама запускает сервер и делает `initialize`) |
| список серверов | `ragraf: …ragraf-mcp.py --agent claude-code … - √ Connected` | `claude mcp list` |
| повторная запись того же имени | отказ `MCP server ragraf already exists in user config`, код 1 | второй `claude mcp add-json` |
| файл настроек хуков | `~/.claude/settings.json`, ключ `hooks` | документация клиента и запись установщика |
| событий хуков в протоколе | 9 (`PreToolUse`, `PostToolUse`, `Notification`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PreCompact`, `SessionStart`, `SessionEnd`) | документация клиента, раздел Hook Events |
| подключено событий | 4 | `~/.claude/settings.json`, проверка `--check` |
| смоук модели | `Not logged in · Please run /login`, код 1 (смоук переводит в 3) | `claude -p "ответь одним словом: ok"` |
| `--bare` | отключает хуки и автопоиск `CLAUDE.md` | `claude --help`, описание флага |
| невалидные настройки в `-p` | **молча игнорируются** | `claude --help`: «Settings files that fail validation are silently ignored in this mode» |

Последняя строка — причина, по которой установщик проверяет `settings.json`
разбором и прогоном хуков: сломанный файл в неинтерактивном режиме не даёт ни
ошибки, ни предупреждения, и «настройка есть» превращается в «настройки нет».

## 3. Установка: одна команда

**Плагин (предпочтительно).** Claude Code 2.1.316 умеет ставить MCP-сервер, хуки,
навык и команды одним пакетом; для RAGRAF такой пакет собран и проверен — см.
`docs/03_implementation/CLAUDE_PLUGIN.md`. Коротко:

```text
/plugin marketplace add paulmann/RAGRAF
/plugin install ragraf@ragraf
```

Отличие, которое надо знать: у плагинных серверов другое имя инструмента
(`mcp__plugin_ragraf_ragraf__ragraf_*` вместо `mcp__ragraf__ragraf_*`), поэтому
навык и матчер хуков в плагине свои. Ручная установка ниже остаётся рабочим
способом для тех, кто плагины не ставит; вместе их ставить нельзя — хуки
сработали бы дважды (`--plugin --replace` снимает ручную установку).


```powershell
python tools/install_claude_code.py            # установка + проверка
python tools/install_claude_code.py --check    # только состояние (код 0/1)
python tools/install_claude_code.py --dry-run  # показать, ничего не меняя
python tools/install_claude_code.py --remove   # откат с резервными копиями
```

Что делает команда:

1. **Хуки.** Идемпотентно вписывает четыре события в `~/.claude/settings.json`:
   свои записи снимаются и добавляются заново (правка времени ожидания или
   matcher применяется, копии не плодятся), чужие записи в тех же событиях
   остаются нетронутыми. Файл пишется UTF-8 без BOM с переводами строк LF;
   перед изменением — копия `settings.json.bak-<метка времени>`.
2. **Права.** Добавляет в `permissions.allow` ровно одно правило —
   `mcp__ragraf__*`: вызовы инструментов индекса не спрашивают подтверждения.
   Права на правку файлов и запуск команд установщик не трогает.
3. **MCP.** Зовёт команду продукта `claude mcp add-json --scope user ragraf
   <json>`; на ответ «already exists» запись снимается и добавляется заново
   (иначе повторный запуск падал бы кодом 1). Значения: интерпретатор из
   `.venv`, `tools/ragraf-mcp.py`, `--agent claude-code --agent-kind external`,
   `PYTHONIOENCODING=utf-8` и `PYTHONUTF8=1`.
4. **Память.** Дописывает в `~/.claude/CLAUDE.md` раздел правил между
   маркерами `<!-- == RAGRAF … -->` и `<!-- == конец блока RAGRAF -->`; при
   повторном запуске блок не дублируется, при откате снимается вместе с
   маркерами, а текст владельца вокруг остаётся.
5. **Навыки.** Копирует `docs/skills/ragraf-core` и `docs/skills/ragraf-secrets`
   в `~/.claude/skills/`; повторный запуск проверяет побайтовое совпадение и
   ничего не перезаписывает зря.

Идемпотентность измерена: второй прогон печатает «добавлено 4, снято 4, файл не
менялся», метка задачи и навыки — «уже есть» и «совпадает».

Песочница: `--home <каталог>` переводит все пути (настройки, `CLAUDE.md`,
навыки, состояние клиента) в указанный каталог и не зовёт `claude` — так
установка проверяется, не трогая рабочую учётную запись. Именно этим путём
прогоняется `tests/test_claude_code_integration.py`.

Ручной путь без установщика:

```powershell
claude mcp add-json --scope user ragraf '{"type":"stdio","command":"<RAGRAF>\.venv\Scripts\python.exe","args":["<RAGRAF>\tools\ragraf-mcp.py","--agent","claude-code","--agent-kind","external"],"env":{"PYTHONIOENCODING":"utf-8","PYTHONUTF8":"1"}}'
```

Дальше — блок хуков из `integrations/claude-code/settings.template.json` и
раздел правил из `integrations/claude-code/CLAUDE-section.md`.

## 4. Проверка

`python tools/install_claude_code.py --check` выполняет 8 проверок и печатает
вердикт; код возврата 0 — готово, 1 — нет:

| Проверка | Что доказывает |
|---|---|
| `settings.json` разбирается | файл не сломан; в режиме `-p` сломанный файл был бы молча проигнорирован |
| все четыре события хуков на месте | записи наши (узнаются по пути скрипта в команде), а не похожие |
| право `mcp__ragraf__*` выдано | вызовы индекса не будут спрашивать подтверждения |
| раздел правил в `CLAUDE.md` на месте | маркеры целы, блок не потерян при правках владельца |
| навыки развёрнуты | `SKILL.md` есть у обоих навыков |
| хук `SessionStart` отвечает `hookEventName=SessionStart` | хук запускается той же командой, что у клиента, и отдаёт непустой `additionalContext` |
| хук `PreToolUse` отдаёт решение по протоколу | гейт отвечает `allow`/`ask` на пробный payload, а не падает |
| MCP-сервер отвечает на рукопожатие | `claude mcp get ragraf` → `Status: √ Connected` — сервер поднимается и проходит `initialize` |

Две проверки хуков запускают команду **как клиент** — строкой, через оболочку,
с JSON на stdin. Это ловит то, чего не видно по настройкам: неверный
интерпретатор, потерянный путь, падение на первом русском ответе.

Проверка без модели и проверка с моделью — разные вещи, и они названы
раздельно:

```powershell
claude mcp get ragraf                       # без входа: Connected / отказ
pwsh -NoProfile -File integrations/claude-code/smoke.ps1   # с моделью: нужен /login
```

Замер 02.11.2026: `claude mcp get ragraf` → `Status: √ Connected`, то есть
сервер RAGRAF проходит `initialize` без авторизации. Смоук с моделью без входа
возвращает код 3 (`Not logged in · Please run /login`) — это граница, а не
дефект интеграции.

## 5. Поведение клиента: что поддерживает и что игнорирует

| Возможность | Claude Code 2.1.316 | Замечание |
|---|---|---|
| MCP stdio, область `user` | да | `claude mcp add-json --scope user` |
| MCP-серверы области `project` | да | файл `.mcp.json` в корне проекта; сервер показан как «Pending approval», пока проект не одобрен |
| хуки в `settings.json` | да | 9 событий; `matcher` применяется только к `PreToolUse` и `PostToolUse` |
| вывод хука | да | `hookSpecificOutput` с `hookEventName`; код возврата 2 блокирует вызов и передаёт `stderr` модели |
| `additionalContext` для `SessionStart` / `UserPromptSubmit` / `PostToolUse` | да | несколько значений склеиваются |
| `additionalContext` для `Stop` | **нет** | строка отчёта видна в режиме транскрипта (`Ctrl-R`) — ограничение клиента |
| `permissions.allow` | да | правило `mcp__ragraf__*` |
| навыки `~/.claude/skills/<имя>/SKILL.md` | да | имя и описание берутся из frontmatter |
| память `~/.claude/CLAUDE.md` | да | читается автоматически; `--bare` автопоиск отключает |
| флаг `--bare` | отключает хуки и `CLAUDE.md` | интеграция в этом режиме не работает — и это ожидаемо |
| невалидный `settings.json` в `-p` | молча игнорируется | отсюда обязательная проверка разбором |

## 6. Границы

* **Смоук модели требует входа.** Без `/login` клиент отвечает `Not logged in`;
  проверки без модели (MCP-рукопожатие, хуки на payload) от входа не зависят и
  выполняются всегда. Это названо числом кода возврата: 3.
* **Гейт не переписывает вызов.** Протокол разбирает `updatedInput`, но не
  применяет его: подсказка «сначала `search`» предлагается текстом, а отказ
  блокирует конкретный вызов. Заставить агента переделать шаг нельзя.
* **Корпус определяется по рабочему каталогу процесса сервера.** Если клиент
  запускает сервер не в каталоге проекта, корпус не найдётся: инструменты
  ответят «корпус не выбран», и это лечится операцией `use_project`, а не
  догадкой.
* **Один индекс на машину.** Корпус общий с AutoClaw и HARNESS; параллельная
  переиндексация из двух клиентов — это две записи в одну ревизию, чего RAGRAF
  не запрещает, но и не приветствует (сторож увидит расхождение суммы).
* **Права выдаёт владелец.** Установщик добавляет только `mcp__ragraf__*`;
  права на правку файлов и запуск команд остаются решением владельца.
* **Стенд отдельный.** Чистые установки — только на 192.168.31.103: на рабочей
  машине живёт индекс.

## 7. Откат

```powershell
python tools/install_claude_code.py --remove
```

Снимаются: четыре записи хуков (только наши — узнаются по пути скрипта),
правило `mcp__ragraf__*`, запись MCP-сервера, раздел правил из `CLAUDE.md`,
каталоги навыков. Рядом с каждым изменённым файлом остаётся копия
`<имя>.bak-<метка времени>`; пустой корень `~/.claude/skills` убирается, чтобы
не выглядеть установленным навыком без содержимого.

Проверка отката замерена в песочнице: после `--remove` файлы
`settings.json` и `CLAUDE.md` удаляются (если своих записей в них не было),
`--check` возвращает код 1 и перечисляет, чего не хватает. Откат не удаляет
`~/.claude.json` — в нём живёт состояние клиента, а не только наша запись.
