# Темы документного графа: кластеры и сводки

Документ описывает этап 5 плана «Агентские интеграции и документный граф». Здесь
записано, что считается темой, почему кластеризация детерминированная, чем
проверено и где границы.

## 1. Зачем темы, если есть сущности

Слой фактов отвечает на вопросы «кто рядом с этой сущностью» (`entity_neighbors`)
и «какие документы связаны» (`doc_relations`). Он не отвечает на вопрос «о чём
этот корпус»: у сущностей нет ни групп, ни заголовка, ни карты. Агент, впервые
пришедший в чужой проект, тратит первые обращения именно на это.

Тема — группа сущностей, которые встречаются вместе чаще случайного, плюс
адреса, по которым её можно проверить, и (если модель была доступна) короткая
сводка по цитатам участников.

| Вопрос | Операция | Что показывает |
|---|---|---|
| О чём корпус | `global_overview` | документы, сущности, связи, темы, сводки и топ-темы с адресами |
| Какие темы есть и кто в них | `themes` | кластеры: участники, вес, адреса цитат, сводка либо `summary=null` |

Обе операции объявлены возможностью `doc-graph` (издание pro): они читают тот же
слой, что и `entity_neighbors`, и закрыты тем же гейтом.

## 2. Кластеризация: детерминированная, без Leiden

Порядок сборки (`themes.build`):

1. **Со-встречаемость.** Ребро между двумя сущностями — их совместное упоминание в
   одном чанке; вес ребра — число таких чанков. Пара внутри одного чанка считается
   один раз: повтор в тексте не делает связь крепче.
2. **Порог.** Рёбра слабее `min_weight` (по умолчанию 2) отбрасываются. Порог —
   решение, а не украшение: при 1 темой становится любая случайная пара.
3. **Компоненты связности.** Тема — компонента графа. Детерминированный обход:
   старт с лексикографически наименьшего идентификатора, соседи — по сортировке.
4. **Разрез крупной компоненты.** Компонента больше `max_size` (по умолчанию 40)
   режется по порядку силы: сначала сумма весов рёбер, потом нормализованное имя,
   потом идентификатор. Полное равенство разрешается идентификатором, поэтому
   разрез не зависит от порядка обхода.
5. **Затравка и заголовок.** `seed_entity_id` — сущность с максимумом упоминаний,
   при равенстве — лексикографически первая. Заголовок без модели — её
   нормализованное имя.

`theme_id` считается той же функцией, что и при записи (`docgraph.theme_id`):
`sha1(seed_entity_id + '|' + отсортированные участники)`. Отсюда два свойства,
которые проверяются, а не обещаются: идентификатор одинаков на любой машине и не
меняется от порядка обхода.

## 3. Где считается и когда пишется

Темы строятся **в том же проходе**, что и факты (`docgraph build` /
`index --doc-graph`): сразу после записи сущностей и связей. Это бесплатная часть —
модель для кластеров не нужна.

Отдельная команда `ragraf docgraph themes` пересобирает темы из уже собранного
слоя: без сети и без обращений к провайдеру. Она же нужна, когда слой собран
раньше, чем появились темы: без неё «тем нет» означало бы «не построены».

Флаг `--summaries` добавляет сводки — это уже платно (одно обращение на тему) и
только при настроенной модели.

**Пересборка тем удаляет сводки этой ревизии.** Сводка описывает состав темы; если
состав изменился, старый текст относится к другому набору участников. Показывать
его как сводку текущей темы значило бы выдавать прошлое за настоящее.

## 4. Сводка: строгий JSON и проверка цитат

Сводка пишется моделью по цитатам участников (`themes.summaries`). Во входе —
заголовок темы и до восьми цитат с адресами; текст берётся из чанка по смещениям
упоминания, а не из копии в слое (слой не дублирует корпус).

Ответ разбирается строго: `{"summary": "...", "citations": ["path:12"]}`.

| Проверка | Что происходит при нарушении |
|---|---|
| `summary` не пуст и короче предела | отказ разбора, запись не делается |
| `citations` не пуст | отказ: «сводка без цитат» |
| каждая цитата есть среди адресов участников | отказ: «цитаты вне списка» |
| ответ провайдера | отказ называется кодом, остальные темы продолжаются |

Отвергнутая сводка не записывается вовсе — и это проверяется с двух сторон:
разбор не пропускает пустые цитаты, а чтение (`_summary_of`) не выдаёт сводку без
цитат даже если строка в хранилище появилась в обход разбора.

## 5. Пустота названа кодом

| Код | Когда | Что делать читателю |
|---|---|---|
| `edition` | возможность `doc-graph` недоступна изданию | включить издание pro либо читать граф соседей |
| `layer_empty` | слоя нет или в нём нет сущностей | `docgraph build` |
| `themes_not_built` | слой есть, тем нет | `ragraf docgraph themes` (бесплатно) |
| `no_cooccurrence` | область сузила тему до пустоты | расширить `scope` |
| `llm_unavailable` | сводки нужны, а модель не настроена | настроить `llm_*`; темы на месте |
| `summary_rejected` | ответ модели не прошёл проверку | посмотреть `notes`, переформулировать нельзя — это ответ модели |

`found=false` с причиной и `error` — разные ответы: «тем нет» это состояние
слоя, а «слоя нет» это отказ с причиной, как у остальных операций графа.

## 6. Границы

* **Тема — не смысловая категория.** Это совместная встречаемость в чанках.
  Две сущности в одном абзаце дают ребро; «относятся к одной области» этим не
  доказывается.
* **Порог и предел — решения.** `min_weight=2` и `max_size=40` объявлены в ответе
  (`limits_declared`); менять их — правка кода с замером, а не настройка «на глаз».
* **Сводка не пересказывает документы.** Она говорит, что общего у цитат; факты
  остаются за адресами.
* **Область (`scope`) сужает по адресам.** Тема, у которой ни один участник не
  упоминается под областью, в ответ не попадает — это и есть «нет в этой области».

## 8. Чем проверено

Набор `tests/test_docgraph_themes.py` — 40 проверок, песочница (свой каталог
состояния, свой корпус, поддельные провайдеры извлечения и сводок):

| Раздел | Что утверждает |
|---|---|
| 0 | слой собран, тем не меньше двух (иначе проверять нечего) |
| 1 | `theme_id` вычислим из seed и отсортированных участников; повторная сборка даёт те же идентификаторы; в теме не меньше двух участников |
| 2 | у каждого участника и у каждой темы есть адрес в форме `path:строка` |
| 3 | сводки пишутся с цитатами; пустые цитаты и выдуманный адрес отвергаются; сводка без цитат не выдаётся даже из хранилища |
| 4 | обе операции под Community отказывают с названием издания и возможности; объявлены в `doc-graph` (pro); инструменты и метаданные MCP на месте |
| 5 | при разрешённой возможности: темы с адресами, область сужает по адресам, карта считает состав и отдаёт топ-темы с цитатами |
| 6 | «тем нет» и «слой не собран» — разные ответы, у первого названо действие |
| 7 | `docgraph themes` строит темы без модели |

Подсадки (`stage-docgraph/mutations5.py`, работают на копии дерева в `%TEMP%`,
живые исходники не меняются, sha256 сверяется):
`theme_id` не по формуле — 1 провал; тема без участников выдаётся — 1; сводка без
цитат выдаётся из хранилища — 1; гейт снят (возможность объявлена community) — 5.
