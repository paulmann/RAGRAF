## 2. Задача этапа

1. **Каноническое описание и хеш.** Для каждой операции — имя, параметры с
   умолчаниями, ключи ответа — в одной канонической форме и `sha256`.
   Отсортированность, отсутствие пробелов и стабильный порядок обязательны:
   иначе два прогона на неизменном коде дают разные хеши.
2. **Хранилище пинов.** Таблица `op_pin` в `control.sqlite`: `op`, `hash`,
   `approved_at`, `approved_by`, `note`. Второго файла состояния не заводить —
   пин относится к корпусу, как и ревизии.
3. **Наблюдение.** Каждый вызов пишет `observed_hash` в `usage_call` (колонка
   добавляется догоняющей миграцией).
4. **События.** `pin_mismatch` — хеш описания не совпал с пиннутым: в ответе оба
   хеша и ВОЗРАСТ пина. `pin_break` — ошибка аргументов или `unknown_name` ПОСЛЕ
   расхождения, со ссылкой на событие расхождения: это уже поломка клиента, а не
   подозрение.
5. **Операции:** `contract_pin_status` (что пиннуто, что разошлось, возраст),
   `contract_pin_approve` (подтвердить текущее описание человеком). Возможность
   `contract-pin`, издание Enterprise.
6. **Ничего не автоподтверждать.** Пин ставится на релиз; при расхождении RAGRAF
   сообщает, а не «чинит» пин сам.

## 3. Чего НЕ делать

- Не заводить второе описание поверхности: только `surface`.
- Не переписывать `usage_call` целиком: колонка добавляется миграцией, старые
  записи остаются с `NULL` и считаются «не наблюдалось».
- Не подтверждать пин автоматически и не «забывать» расхождение по таймауту.
- Не шуметь на неизменённых операциях: молчание — часть контракта.
- Не ходить в LLM и сеть; наборы герметичны.
- Не коммитить: в дереве нет `.git`.

## 4. Приёмка (`tests/test_contract_pin.py`, группа core, песочница %TEMP%)

1. Изменение умолчания параметра → `pin_mismatch` с обоими хешами и возрастом.
2. Подтверждение (`contract_pin_approve`) → событие исчезает, повторный вызов
   молчит.
3. Вызов со старыми аргументами после расхождения → `pin_break`, связанный с
   событием расхождения.
4. Нетронутые операции не шумят: в отчёте ноль событий на них.
5. Пин переживает перезапуск процесса (читается из `control.sqlite`).
6. Детерминизм: одинаковое описание → одинаковый хеш; изменённое умолчание →
   другой хеш.
7. Без лицензии Enterprise операции отказывают, называя возможность
   `contract-pin`; отказ идёт через `util.next_action`.
8. Подсадка: если канонизация перестанет сортировать ключи, набор падает (два
   прогона дадут разные хеши).

Дополнительно в том же прогоне: `tests/test_preflight.py` — 34/0;
`tests/test_quality_cases.py` — 49/0; `tests/test_quality_loop.py` — 158/0;
`tests/test_editions.py` — 120/0.
