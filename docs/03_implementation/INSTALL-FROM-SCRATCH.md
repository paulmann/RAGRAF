## 1. Что было сломано на чистой установке (замеры до правки)

Колесо `ragraf-0.5.6-py3-none-any.whl` (1 049 166 байт, sha256 `c8af28e2…`),
свежий venv, Python 3.13.18 (python-build-standalone, скачан в домашний каталог —
sudo на хосте нет).

| Шаг документа | Факт | Почему |
|---|---|---|
| `pip install` колеса | **отказ** `ERROR: Package 'ragraf' requires a different Python: 3.11.2 not in '>=3.13'` | на хосте только 3.11, а зависимость `fastembed>=0.8` требует ≥3.12 (`meson-python: The package requires Python version >=3.12`). Требование 3.13 не завышено — но документ не говорил, откуда взять 3.13 |
| `ragraf init proj` | конфиг лёг в **`venv/lib/python3.13/config/proj.yaml`** | `paths.REPO = parents[2]` от `src/ragraf/paths.py`; в колесе это каталог интерпретатора |
| повторный `ragraf init proj` | отказ `конфигурация уже существует: …/venv/lib/python3.13/config/proj.yaml` | видит собственный файл внутри venv |
| `ragraf ensure proj` | **повис без вывода 10+ минут** | тянул модель эмбеддингов с HuggingFace; ни строки о причине, ни флага «без векторов» |
| MCP-сервер на установке | **запустить нечем** | в `[project.scripts]` была одна команда `ragraf`; `tools/ragraf-mcp.py` в колесо не попадает |
| лицензия | искалась в `REPO/catalog/edition.license`, то есть в venv | платное издание на установке не включилось бы никогда |

**Ключевой вывод:** состояние продукта (реестр, настройки, секреты, лицензия,
конфиги корпусов) лежало ВНУТРИ каталога интерпретатора. Обновление venv
(`pip install -U`, пересоздание окружения) уносит его вместе с интерпретатором.

## 2. Что исправлено

### 2.1 Путь состояния: три явных уровня

`src/ragraf/paths.py`: `catalog_dir()` и `config_dir()` выбирают путь так:

1. переменная окружения (`RAGRAF_CATALOG_DIR`, `RAGRAF_CONFIG_DIR`,
   `RAGRAF_SETTINGS_PATH`) — сильнее всего;
2. **рабочая копия** — рядом с кодом есть `pyproject.toml` и `src/ragraf`
   (признак `is_checkout()`), тогда путь остаётся прежним: `<корень>/catalog`,
   `<корень>/config`;
3. **установка** — `~/.ragraf/catalog`, `~/.ragraf/config`
   (`RAGRAF_HOME` отводит домашний каталог целиком).

Тем же правилом пользуются места, которые считали путь сами: `edition.py`
(лицензия и открытый ключ), `admin_server.py` (снимки панели),
`client_setup.py` (конфиг для автозапуска клиента), `attest.py` (конфиг по
умолчанию). `paths.describe()` теперь называет не только путь, но и
происхождение: `env` / `checkout` / `home`, плюс `install_root` и `layout`.

**Замер после правки** (тот же хост, тот же venv, новое колесо 1 051 222 байта,
sha256 `6cb8dde9…`):

```
$ ragraf init proj
конфигурация создана: /home/cbs-test/.ragraf/config/proj.yaml
$ ragraf ensure --no-vectors proj
[ensure] корпус создан и проиндексирован
  ревизия: rev-0001   файлов: 4   время: 0.44 с
$ ragraf -p ~/.ragraf/config/proj.yaml query search "total items"
  1.806  src/report.py:3-4
  1.782  src/calc.py:4-5
$ find ~/.ragraf -maxdepth 2 -type d
~/.ragraf  ~/.ragraf/catalog  ~/.ragraf/config  ~/.ragraf/models
```

### 2.2 `ensure --no-vectors`

`ensure(..., with_vectors=True)` и CLI-флаг; значение проведено насквозь
`ensure → watch.check → run_reindex → Indexer.run`. Перед стадией векторов, если
модели нет в кэше, в отчёт индексации добавляется строка: начинается загрузка
(ориентир ~240 МБ), а без сети — `--no-vectors`.

**Ограничение названо честно:** на модели-кэше поиск по русскому запросу к
английскому коду без векторов ничего не находит (`found=False`) — лексика
работает только по совпадающим словам. Это не дефект, а цена режима без модели.

### 2.3 Команды установки

`[project.scripts]` теперь объявляет три команды, все — в пакет, а не в `tools/`:

| Команда | Цель |
|---|---|
| `ragraf` | `ragraf.cli:main` |
| `ragraf-mcp` | `ragraf.mcp_server:main` |
| `ragraf-admin` | `ragraf.admin_server:main_cli` (обёртка: `main(argv)` требует аргументов, console-script зовёт без них) |

**Замер:** на чистой установке `ragraf-mcp --project ~/.ragraf/config/proj.yaml`
отвечает на `initialize` (`serverInfo: ragraf 0.5.6, tools: 69`) — MCP-сервер
работает из колеса.

### 2.4 Лицензионный гейт (критерий 3)

Тот же хост, чистая установка, лицензии нет:

```
издание: community   возможностей: 6 (documents, search, graph, schema, db-live, audit)
$ tools/call ragraf_siem_export
ОШИБКА: EditionRefusal: операция «siem_export» не входит в издание community:
        возможность «siem-export» появляется в издании enterprise
```

На рабочей машине с действующей лицензией Enterprise (`Mikhail Deynekin, срок
2036-10-22`) та же операция разрешена — то есть гейт зависит от лицензии, а не
от пути запуска.

### 2.5 Обновление без потери индекса (критерий 2)

Сборки 0.6.0 нет, поэтому мерилось на 0.5.0 → 0.5.6. Артефакт 0.5.0
**реконструирован**: нет ни релиза, ни тега, поэтому колесо собрано из текущего
дерева с `__version__ = "0.5.0"` (это единственное отличие; так измеряется путь
обновления, а не конкретный исторический выпуск).

```
ставим 0.5.0 → ragraf --version → 0.5.0
              ragraf catalog → proj, ревизия rev-0001, capability=degraded
обновляем   → ragraf --version → 0.5.6
              ragraf catalog → proj, ревизия rev-0001 (та же), состояние «проиндексирована»
              ragraf query search "total items" → попадания есть
```

Реестр и ревизия сохраняются, переиндексации не происходит.

**Контраст — почему это заслуга правки.** Сборка ДО исправления на том же хосте:

```
$ ragraf init proj3
конфигурация создана: /home/cbs-test/i15-clean/venv3/lib/python3.13/config/proj3.yaml
```

То есть до правки обновление venv уносит состояние: новая версия ищет его в
`~/.ragraf` и корпуса не видит.

## 4. Как повторить замер на чистой машине

```bash
# 1. Python 3.13 без sudo (python-build-standalone), Debian 12:
curl -sSL -o py.tar.gz https://github.com/astral-sh/python-build-standalone/releases/download/20261026/cpython-3.13.18+20261026-x86_64-unknown-linux-gnu-install_only.tar.gz
mkdir -p python && tar xzf py.tar.gz -C python --strip-components=1
./python/bin/python3 -V            # 3.13.18

# 2. venv и установка колеса
./python/bin/python3 -m venv venv
./venv/bin/pip install ragraf-0.5.6-py3-none-any.whl
./venv/bin/ragraf --version

# 3. корпус без загрузки модели.
#    Каталог проекта создаётся ЗАРАНЕЕ и с маркером: `init` отказывает
#    несуществующему каталогу, `ensure` — каталогу без маркера проекта
#    (.git, .gitignore, pyproject.toml…), а `init` требует >= 3 файлов кода.
#    Проверено 01.11.2026: без этих трёх строк шаг 3 не проходит.
mkdir -p proj/src && echo probe > proj/.gitignore
printf 'def total_items(rows):\n    return len(rows)\n' > proj/src/calc.py
printf 'def scale(v):\n    return v * 2\n' > proj/src/util.py
printf 'from calc import total_items\nprint(total_items([1, 2, 3]))\n' > proj/src/report.py
./venv/bin/ragraf init proj
./venv/bin/ragraf ensure --no-vectors proj
./venv/bin/ragraf -p ~/.ragraf/config/proj.yaml query search "total items"

# 4. MCP из установленного пакета
./venv/bin/ragraf-mcp --project ~/.ragraf/config/proj.yaml

# 5. гейт издания (лицензии нет → community)
printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"ragraf_siem_export","arguments":{}}}' \
  | ./venv/bin/ragraf-mcp --project ~/.ragraf/config/proj.yaml
```

Колесо собирается в рабочей копии так (в этой среде `python -m build` требует
установленного `wheel`-дистрибутива и падает на изоляции):

```powershell
python -m pip wheel . --no-deps --no-build-isolation -w <каталог>
```

## 5. Что осталось за границей этапа

1. **Предел ожидания загрузки модели не введён.** Watchdog над сетевой
   библиотекой требует отдельного решения (поток, отмена, цена при быстрой
   сети). Сейчас вместо молчания — названное ожидание и путь без сети.
2. **HTTP-транспорт MCP (`tools/ragraf-mcp-http.py`) в колесо не входит** и
   командой не объявлен: на установке доступен stdio-путь. Перенос скрипта в
   пакет — отдельная работа со своими проверками.
3. **Артефакт 0.5.0 реконструирован** (см. §2.5): настоящего релиза 0.5.0 нет,
   поэтому «обновление с 0.5.0» измерено на сборке с той же версией в
   метаданных и тем же кодом, кроме номера.
4. **`scripts/install.ps1` (путь Windows) этим этапом не менялся** — он и был
   проверенным; проверялся путь `venv + pip`, который README называл
   непроверенным.

**Две ловушки воспроизведения, которых в §4 не было.**

1. `ragraf init proj` ждёт, что каталог `proj` уже существует: на пустом месте
   ответ `не удалось собрать корпус: каталог не существует: …/proj`. В §4 шаг 3
   это подразумевалось, но не было сказано.
2. `ragraf ensure` отказывает каталогу без маркера проекта (`.git`, `.gitignore`,
   `pyproject.toml`, `package.json` и т. п.) с ответом «каталог не является
   проектом», а `init` требует не меньше трёх файлов кода («найдено 2 — слишком
   мало»). То есть перед установкой нужен каталог с маркером и тремя файлами, а
   не пустая папка.

**Найдено и исправлено по ходу замера.** На чистой установке сервер писал в
stderr при каждом запуске: «поверхность инструментов расходится с обработчиками:
без обработчика —, без описания —, без классификации `['ragraf_compact',
'ragraf_excludes']`». Причина: у двух инструментов не было записи в таблице
`_TOOL_META`, поэтому клиент получал пустые `annotations` и не мог отличить
чтение от записи — ровно тот дефект, ради которого таблица заведена. Исправлено
в `src/ragraf/mcp_server.py`; проверка добавлена в `tests/test_mcp.py`: у каждого
инструмента обязан быть `title` и `readOnlyHint`, иначе набор красный.
