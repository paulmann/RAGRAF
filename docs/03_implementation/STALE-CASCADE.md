# Каскад устаревания по рёбрам «факт → факт»

Этап X7, работа A. Вопрос, на который отвечает слой: **если изменилось
допущение, какие выводы на нём держались.** Без этого `stale` помечал файл, но не
цепочку выводов, и «пересчитать» оставалось пожеланием в отчёте.

## 2. Почему отдельная таблица, а не колонка в `stale_edge`

`stale_edge` живёт в журнале управления и описывает рёбра графа **кода**
(`index_rev`, `edge_uid`). Факты живут в документном хранилище и считаются по
`rev_id`. Одна таблица на два хранилища склеила бы разные часы: ревизия документа
и ревизия индекса совпадают не всегда, а ротация ревизий удаляет строки по
колонке `rev_id` — и не увидела бы третий файл.

Поэтому `fact_stale` несёт `rev_id` и попадает под ту же ротацию, что
`fact_assertion` и `derivation_edge`.

## 3. Что считается изменением входа

Два источника, и оба — замер, а не догадка:

- **при индексации** (`auto_cascade`, `src/ragraf/provenance.py:971`): `sha256`
  версии документа в предыдущей ревизии против текущей. Изменившиеся пути дают
  входные факты, от них идёт каскад. Нет предыдущей ревизии (первый прогон,
  ротация) — каскад не выдумывает изменение и говорит об этом полем `previous`;
- **по запросу** (`stale_cascade --changed`): вызывающий называет факты или
  адреса. Неразрешённая ссылка попадает в `unresolved`, а не исчезает: молча
  проглоченная опечатка выглядит как «зависимостей нет».

## 4. Операция `stale_cascade`

```
python tools/ragraf.py query stale_cascade --changed "path:10,fact-42" --depth 3
python tools/ragraf.py query stale_cascade --changed ... --apply
python tools/ragraf.py query stale_cascade --clear-marks
python tools/ragraf.py query stale_cascade            # что уже помечено
```

| вход | смысл |
|---|---|
| `changed` | факты или адреса через запятую |
| `depth` | предел обхода, 1..10, по умолчанию 3 |
| `apply` | поставить пометки (без него — только отчёт) |
| `clear-marks` | закрыть пометки: пересчёт выполнен |
| `limit` | предел выдачи при чтении пометок |

Отказы названы причиной, а не пустотой: `apply` и `clear-marks` вместе — «одно
действие на вызов»; `apply` без `changed` — «не названо, что изменилось».

Строка отчёта: `fact_id`, адрес `path:строки`, `distance`, провенанс, действие
(`пересчитать` / `решение человека`), `cause_fact_id` (изменённый вход, от
которого идёт цепочка) и `input_fact_id` (ближайший вход). Помечаются только
выводы: утверждение человека пересчитать автоматически нельзя — за него отвечает
человек, и это названо в `skipped_stated`.

За пределом глубины факты не теряются: `outside_cap`. Факт без адреса не
выдаётся и считается в `rejected_no_citation`.

## 5. Границы, названные прямо

- Изменение входа доказывается `sha256` **версии документа**, а не смыслом
  правки: правка одного слова помечает весь документ изменённым. Поэтому пометка
  — «пересчитать», а не «удалить»: производный факт остаётся в слое с адресом.
- Пометки относятся к ревизии: после переиндексации прежние не видны, и это
  честнее «вечной» пометки, которая пережила бы свой вход.
- Автоматика помечает, но не пересчитывает: пересчёт — это повторный проход
  извлечения (модель, стоимость), и решение о нём остаётся за человеком.
