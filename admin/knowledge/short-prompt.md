# Короткий промт: контур «Знания агентов»

> Версия для быстрого запуска. Полная постановка — `PROMPT-agent-knowledge.md`.
> Хост: DeepSeek Harness 0.2.0-rc.2; AutoClaw 2 (zwork 2.2.2) — read-only источник.

## Роль

Ты — senior product engineer, владелец сквозного контура знаний LLM-агентов. Сначала факты и ADR, потом код. Не переизобретай существующее: в HARNESS уже есть история сессий, навыки, `session-query` и команды агентов.

## Цель

По вопросу находить: кто уже решал задачу, какие навыки и знания нужны, чем это подтверждено, — и дать агенту-руководителю передать задачу подходящему агенту с полным контекстом.

## Что использовать, а не писать заново

- **История HARNESS** — `ctx.sessionQuery`; сессии `~/.dsh/sessions/**/session.v4.jsonl.zstd`, проекции `~/.dsh/storages/session_projcache/sessions/*.json`.
- **Полнотекстовый поиск** — включить `dsh-session-query-sqlite` с персистентным путём (`openAt: startup|first-search`); сейчас он `:memory:` + `never`.
- **Навыки** — `ctx.skills`, `SKILL.md`; индексировать frontmatter + тело + `whenToUse` + ресурсы; использование брать из `tool/call name="skill"`.
- **Настройки** — `dsh-settings`; расписание — `dsh-schedule`; фоновые задачи — `dsh-jobs-local`.
- **Диспетчеризация** — `dsh-experimental-agent-team`: `spawn_teammate`, `team_task_*`, `send_message`.
- **AutoClaw 2** — read-only `runtime.sqlite` (`work_sessions`, `work_runs`, `work_events`, `neutral_session_entries`, `memory_assets`, `agents`, `collaboration_run_agent_*`) и `zwork-agent/skills` + `skills-preinstall.json`.

## Обязательный минимум

1. **Настройки:** секция «Знания агентов», включена по умолчанию; отключение останавливает индексацию и инструменты; статус, расписание, источники, приватность, ручной reindex.
2. **Индексация:** 2 раза в сутки (03:00/15:00, локальная зона, настраивается), инкрементально, без пересечений, с догоном последнего пропуска; ручной `knowledge_reindex` (`incremental|full|verify`).
3. **Модель:** `актор → эпизод → навык → артефакт → назначение`; provenance `source/session_id/event_seq/time/workspace/content_hash`.
4. **Поиск:** `find_agent`, `find_skill`, `find_knowledge`; FTS5 + опционально вектор; фильтры; агрегация по актору; доказательства в каждом результате.
5. **Карточка навыка:** тело, `whenToUse`, ресурсы, версия/хэш, кто и когда применял, итоги, применимость к задаче, чек-лист и типичные ошибки.
6. **Диспетчеризация:** `knowledge_dispatch`; по умолчанию `dry_run`; при `commit` — задача/сообщение/реплика с пакетом контекста и критериями приёмки; для AutoClaw — `external_handoff`, без записи в БД.
7. **Приватность:** локально по умолчанию; редакция секретов до записи; исключения; забывание; retention 180 дней; файлы `0600`.
8. **Наблюдаемость:** `knowledge_status` — `index_rev`, последний/следующий запуск, покрытие, размер, ошибки, деградации.

## Критерии приёмки

- Включено по умолчанию; выключение останавливает всё и честно объясняет.
- 2×/сутки по расписанию, без пересечений, с догоном.
- Покрытие 100% доступных сессий/навыков, без дублей.
- Golden set ≥ 30 запросов: top-3 recall ≥ 0.80, MRR ≥ 0.60, zero-result ≤ 10%.
- Карточка навыка содержит тело, `whenToUse`, ресурсы, версию/хэш и доказательства применения.
- `dry_run` ничего не запускает; `commit` создаёт задачу/реплику с provenance; повтор идемпотентен.
- Инкремент после изменения одной сессии индексирует только её; повторный прогон — no-op.
- kill -9 во время индексации не ломает предыдущий индекс.
- Секрет-канарейка не попадает в БД, FTS, логи и выдачу.
- AutoClaw БД после прогона не изменилась (хэш до/после).
- P95 поиска ≤ 300 мс; incremental ≤ 60 с на целевом объёме.

## Этапы

- **P0:** ADR + схема + включение персистентного session-query + DSH-адаптер + акторы/эпизоды/навыки + `status/search/reindex` + настройки + тесты.
- **P1:** AutoClaw read-only + `get_agent/get_skill/get_episode` + карточка навыка + `dispatch` + страница поиска.
- **P2:** опциональная семантика/LLM-суммаризация с согласием, обратная связь, retention/forget UI.
